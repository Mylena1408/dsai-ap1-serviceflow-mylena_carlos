 5. COMO USAR O SISTEMA LOCALMENTE (outro desenvolvedor)
-------------------------------------------------------------------------------

Pre-requisitos e banco de teste: ver MUDANCAS_NO_PROJETO_DIA/2026-10-29_mudancas.txt
(secao 5: Node 22 via "volta run --node 22", PostgreSQL portatil em
../pgtest, .env.test.local).

Novidades de 30/10:

1) Banco de DESENVOLVIMENTO separado do de teste:
     - criar o banco serviceflow_dev no mesmo PostgreSQL;
     - criar .env.local (NAO versionar; ja esta no .gitignore) com:
         NODE_ENV=development
         DATABASE_URL=postgresql://USUARIO:SENHA@127.0.0.1:54329/serviceflow_dev
         AUTH_SECRET=<gerar com: node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))">
     - aplicar as migrations:  npx prisma migrate deploy

2) Dados ficticios (opcional, recomendado):
       npm run seed:demo
   Pode ser executado varias vezes sem duplicar nada. Recusa bancos _test.

3) Subir e acessar:
       npm run dev   ->  http://localhost:3000
   Clicar em "Entrar como Administrador", "Entrar como Solicitante" ou
   "Entrar como Atendente". Nao ha senha. "Sair" volta para o login.
   O formulario de e-mail e senha continua em "Entrar com e-mail e senha"
   (para contas criadas no painel).

4) Rodar os testes:
       npm run lint && npm run typecheck && npm run test:unit
       npm run test:integration
       npm run test:e2e        <- PARE o "npm run dev" antes: o Next 16 nao
                                  permite dois servidores na mesma pasta.
   Com .env.local presente, o E2E nao precisa mais de DATABASE_URL na
   linha de comando.

 6. ARQUITETURA FINAL (apos a SF-043)
-------------------------------------------------------------------------------

src/modules/<modulo>/
  domain/          tipos e regras puras.
                   Lint proibe: Prisma, banco, Next, next-auth, React e
                   importar application/infrastructure/ui.
  application/     casos de uso, ports e schemas de entrada (<nome>-schemas.ts).
                   Lint proibe: Prisma, banco, Next, next-auth, React e
                   importar infrastructure/ui.
  infrastructure/  implementacoes Prisma dos ports.
  ui/              componentes React (so o modulo auth tem). Lint proibe banco.
  index.ts         API publica; outros modulos e src/app so importam daqui.

Comuns:
  src/server/db/prisma-errors.ts            unico lugar que traduz erros Prisma.
  src/server/db/serializable-transaction.ts transacao Serializable comum.
  src/shared/validation                     so schemas genericos.

Area administrativa:
  src/app/(admin)/admin/page.tsx            compoe as secoes.
  src/app/(admin)/admin/_sections/<entidade>/{actions.ts, *-section.tsx}
  src/app/(admin)/admin/_shared/action-helpers.ts
  src/app/(admin)/admin/actions.ts          reexporta as actions (mesmo caminho).

Pontos de composicao fora de src/ (importam arquivos internos de proposito):
  auth.ts                   -> evita ciclo de imports com o Auth.js.
  scripts/bootstrap-admin.ts e scripts/prepare-e2e.ts -> carregam o .env
                               antes de abrir o banco.
